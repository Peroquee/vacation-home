# Security

The app holds guest personal data (DSGVO) and Google OAuth tokens. This page
is the threat checklist from GitLab #93. Each item is marked **addressed**
(with where) or **accepted** (with why). Review it whenever something in its
area changes.

## Threat checklist

| #   | Threat                                                          | Status                                   | How                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --- | --------------------------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Someone outside the household signs in                          | Addressed                                | Google sign-in only, for **verified** emails on `AUTH_ALLOWED_EMAILS` ([`src/auth.ts`](../src/auth.ts)). The list is checked again on **every request** ([`src/proxy.ts`](../src/proxy.ts)), and a session for a removed address is deleted and its cookie cleared. E2E: `e2e/auth.spec.ts`.                                                                                                                                                                              |
| 2   | A stolen or lingering session                                   | Addressed                                | Database sessions (revocable; sign-out deletes the row). The cookie is `HttpOnly` and `SameSite=Lax`, and `Secure` over https.                                                                                                                                                                                                                                                                                                                                            |
| 3   | Cross-site request forgery                                      | Addressed                                | SameSite=Lax cookies, plus a check in the proxy ([`src/lib/csrf.ts`](../src/lib/csrf.ts)): a mutating API call from a browser must come from the app's own origin (`Origin`/`Sec-Fetch-Site`), or it gets `403 forbidden`. Auth.js routes use Auth.js's own CSRF token, and Next checks the origin of server actions (sign-out). E2E: `e2e/security.spec.ts`.                                                                                                             |
| 4   | Cross-site scripting                                            | Addressed                                | React escapes all output, and there's no `dangerouslySetInnerHTML`. A per-request **nonce CSP** with `'strict-dynamic'` means only the app's own scripts run ([`src/lib/security-headers.ts`](../src/lib/security-headers.ts)). Every page renders per request so it gets a nonce. E2E checks the pages run with no CSP violations.                                                                                                                                       |
| 4a  | Inline styles                                                   | Accepted                                 | `style-src` allows `'unsafe-inline'`: the UI components set `style` attributes, which a nonce can't cover. Styles can't run code.                                                                                                                                                                                                                                                                                                                                         |
| 5   | Clickjacking                                                    | Addressed                                | `frame-ancestors 'none'` and `X-Frame-Options: DENY`.                                                                                                                                                                                                                                                                                                                                                                                                                     |
| 6   | Traffic read or altered on the network                          | Accepted on a LAN, addressed over https  | Over https the app sends HSTS and `upgrade-insecure-requests`. A plain-http LAN deployment can't, by nature; **a decision for the owner**: put it behind https (reverse proxy with a local certificate) if the network isn't trusted.                                                                                                                                                                                                                                     |
| 7   | Google tokens stolen from the database or a backup              | Addressed                                | Tokens are sealed with AES-256-GCM under `TOKEN_ENCRYPTION_KEY`, which lives only in the environment, never in the database or backups ([`src/lib/secrets.ts`](../src/lib/secrets.ts)). Sign-in stores no token at all. The key can be rotated without losing connections (below). Test: `connection.db.test.ts` (no plaintext stored), `rotate.db.test.ts`.                                                                                                              |
| 8   | Tokens or personal data leak through logs, errors or the API    | Addressed                                | A scrubbing logger masks emails, tokens and secrets ([`src/lib/scrub.ts`](../src/lib/scrub.ts)). The error tracker collects no bodies, cookies or user info. API responses never carry a token: tested in `cross-account.db.test.ts`. Sync error messages are fixed sentences.                                                                                                                                                                                            |
| 9   | OAuth login CSRF or code injection on the calendar connect flow | Addressed                                | A random `state` in an httpOnly cookie, bound to the user and scoped to the callback path, compared in constant time ([`src/lib/google/state.ts`](../src/lib/google/state.ts)).                                                                                                                                                                                                                                                                                           |
| 10  | Forged Google push notifications                                | Addressed                                | Only a notification naming a channel the app created, with that channel's secret (stored hashed, compared in constant time) and resource id, is accepted. It carries no data and only makes the next poll happen sooner. The webhook is rate limited.                                                                                                                                                                                                                     |
| 11  | Brute force and abuse of sensitive endpoints                    | Addressed                                | Rate limits ([`src/lib/rate-limit.ts`](../src/lib/rate-limit.ts)) answer `429` with `Retry-After`: sign-in 30 per 10 min, webhook 300/min, calendar connect 20 per 10 min, guest erasure 10/h, category reassign and bulk delete 30 per 10 min.                                                                                                                                                                                                                           |
| 11a | Sign-in limit shared by everyone without a trusted proxy        | Accepted                                 | Without `TRUST_PROXY_HEADERS`, the client address can't be trusted, so sign-in and webhook limits count per route. A flood can delay sign-in for the household for minutes, but can't get in. Behind a reverse proxy, set `TRUST_PROXY_HEADERS=true` to count per address.                                                                                                                                                                                                |
| 12  | One user sees another's data                                    | Accepted by design, addressed for Google | Every allow-listed user is part of one household and shares all properties, bookings, guests and the ledger. A **Google connection is personal**: one user can't see, use or remove another's. Tested in `src/app/api/google/cross-account.db.test.ts`.                                                                                                                                                                                                                   |
| 13  | Data of one property attached to another                        | Addressed                                | Composite foreign keys keep a transaction's booking, category type and currency consistent with its property. Block and booking overlap rules are per property.                                                                                                                                                                                                                                                                                                           |
| 14  | Guest personal data kept or spread                              | Addressed                                | Erasure (DSGVO Art. 17) and re-erasure after a restore (`npm run guests:repurge`). No guest data goes to Google, and no event titles or attendees come back. Backups age out (docs/backup-and-restore.md).                                                                                                                                                                                                                                                                |
| 15  | SQL injection                                                   | Addressed                                | Prisma queries are parameterised. Raw SQL uses tagged templates, and the only `$executeRawUnsafe` calls are constant savepoint statements. `LIKE` input is escaped.                                                                                                                                                                                                                                                                                                       |
| 16  | Vulnerable dependencies                                         | Addressed                                | `npm run audit` in CI fails on any high or critical advisory in production dependencies unless it's reviewed in [`security/audit-allowlist.json`](../security/audit-allowlist.json), with a reason and an expiry date. Next was raised to 16.3.8 and `mysql2` overridden to 3.24.5 to clear the advisories found.                                                                                                                                                         |
| 17  | Secrets in the repository or default secrets in production      | Addressed                                | `.env*` files are git-ignored. Configuration is validated at start, and production refuses the `.env.example` placeholders.                                                                                                                                                                                                                                                                                                                                               |
| 18  | Open redirect after sign-in                                     | Addressed                                | `safeCallbackUrl` keeps destinations on the app's own origin, resolved as a browser would. Tested.                                                                                                                                                                                                                                                                                                                                                                        |
| 19  | Server-side request forgery                                     | Addressed                                | The server fetches only fixed Google endpoints, and Next's image optimisation advisory is fixed by the upgrade.                                                                                                                                                                                                                                                                                                                                                           |
| 20  | Expensive queries as denial of service                          | Addressed                                | Page sizes and date ranges are capped on every list and report endpoint.                                                                                                                                                                                                                                                                                                                                                                                                  |
| 21  | Backups readable by whoever holds the share                     | Accepted                                 | Backups hold personal data in plain SQL on the off-host NFS share. They contain no usable Google token (sealed, key elsewhere). Restrict access to the share, as docs/backup-and-restore.md says.                                                                                                                                                                                                                                                                         |
| 22  | A private route becomes reachable without a session             | Addressed                                | Only an explicit allow-list is public ([`src/lib/access.ts`](../src/lib/access.ts)). A unit test walks every route file under `src/app` and fails if any other route answers without a session, or if a public-site route lives outside `src/app/(public)` / `src/app/api/public` ([`src/lib/access.routes.test.ts`](../src/lib/access.routes.test.ts)); `e2e/public-site.spec.ts` requests every method of every other route signed out and expects a redirect or `401`. |
| 23  | The public booking site leaks a session or private data         | Addressed                                | Public paths bypass Auth.js entirely and the proxy strips its cookies before the page runs, so no public response sets or reads a session. Public pages get a stricter CSP (no outside images, forms only to the app, `base-uri 'none'`). The public API answers with an explicit allow-list of fields ([`src/lib/properties/public.ts`](../src/lib/properties/public.ts)); unlisted, archived and unknown properties are the same `404`. E2E: `e2e/public-site.spec.ts`. |
| 24  | Scraping or flooding the public booking site                    | Addressed                                | Rate limits per client: pages 120/min, API 60/min. Without `TRUST_PROXY_HEADERS` they count for everyone together (as in 11a), so a flood can slow the public site for all visitors; set it behind the reverse proxy before the site goes on the internet (GitLab #113).                                                                                                                                                                                                  |
| 25  | Photos reveal where they were taken, or carry harmful content   | Addressed                                | Uploads are checked by their bytes (JPEG, PNG, WebP), capped at 20 MB and 50 megapixels, and re-encoded as WebP with sharp; the upload itself is never stored, so no EXIF/GPS/XMP survives in any format ([`src/lib/listing/photo-processing.ts`](../src/lib/listing/photo-processing.ts)). Photo files are served only for a listed property's own photos, by content hash. Tests: `photo-processing.test.ts`, `listing.db.test.ts`, `e2e/listing.spec.ts`.              |

## Rotating the token key

`TOKEN_ENCRYPTION_KEY` can be replaced without disconnecting anyone:

1. Generate a new key:
   `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`
2. Set it as `TOKEN_ENCRYPTION_KEY`, and put the previous key in
   `TOKEN_ENCRYPTION_KEYS_OLD` (comma-separated, if there are several).
   Restart the app. Tokens sealed under the old key stay readable, since
   each sealed value names its key.
3. Re-seal everything under the new key, with the tools image:
   `docker compose run --rm migrate npm run tokens:rotate` (in development,
   `npm run tokens:rotate`). It prints how many were re-encrypted, and is
   safe to run again.
4. Empty `TOKEN_ENCRYPTION_KEYS_OLD` and restart.

A token sealed under a key that's in neither variable can't be read. The
connection shows "reconnect" (`reason: key_changed`), and `tokens:rotate`
counts it as unreadable.
